# ECA 大厅服务接口说明

> 规范用户文档入口：[`docs/游戏大厅系统/README.md`](../../../../docs/游戏大厅系统/README.md)。本文件保留为接口历史说明；局内私人副本迁移后，ECA 正式入口只使用“大厅服务 - 局内私人副本”。旧“创建私人副本/启动多人私人副本”成对入口已删除，不再作为新项目接口说明。

本模块把项目中的大厅、组队、匹配、聊天和私人副本等用户可感知功能封装为 ECA 可调用的正式 Lua 接口。ECA 作者只需要使用名称以 `大厅服务 - ` 开头的函数，不需要访问 BOB、Client、网络协议或 `MatchTest*`。

## 调用模型

动作函数会立即返回一个 ECA `TABLE`（Lua 侧为原生 `table`），表示请求是否已被本地门面受理：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `accepted` | `boolean` | `true` 表示本地流程已接受；是否产生终态事件取决于接口类型 |
| `reason` | `string` | 受理时为“请求已受理”，拒绝时为具体原因 |
| `request_id` | `string` | 已受理请求的唯一编号；拒绝时为空字符串 |
| `action` | `string` | 动作名称 |
| `sync` | `boolean` | 拒绝结果为 `true`，已受理异步请求为 `false` |
| `result_data` | `TABLE` | 同步补充数据，通常为空 |

拒绝不会触发终态事件。普通异步请求最终只触发一次 `大厅服务请求完成` 自定义事件；同房分流、加入口令和返回大厅是请求提交型跨图接口，不创建可等待 `request_id`，也不触发该事件。事件参数 `回调数据` 是一个 `TABLE`，包含下列字段。事件名称是稳定契约；主关卡当前生成的正式事件编号是 `1876423410`，子关卡自动继承：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `request_id` | `string` | 与动作返回值中的编号一致 |
| `action` | `string` | 动作名称 |
| `success` | `boolean` | 最终是否成功 |
| `reason` | `string` | 最终结果说明或失败原因 |
| `result_data` | `TABLE` | 动作结果数据 |

典型流程：调用动作，先判断 `accepted`；若为 `true`，保存 `request_id`，并在 `大厅服务请求完成` 事件中按该编号关联最终结果。

## 动作接口

| ECA 函数 | 参数 | 说明 |
| --- | --- | --- |
| `大厅服务 - 重建大厅连接` | 无 | 重新创建并等待大厅连接就绪 |
| `大厅服务 - 设置匹配分数` | `分数: integer` | 更新当前玩家的匹配分数 |
| `大厅服务 - 创建队伍` | 无 | 创建最多两人的队伍 |
| `大厅服务 - 加入队伍` | `队伍编号: integer` | 加入指定队伍 |
| `大厅服务 - 离开队伍` | 无 | 离开当前队伍 |
| `大厅服务 - 解散队伍` | 无 | 队长解散当前队伍 |
| `大厅服务 - 转移队长` | `目标AID: integer` | 将队长转移给指定成员 |
| `大厅服务 - 移出队员` | `目标AID: integer` | 将指定成员移出队伍 |
| `大厅服务 - 开始匹配` | `分数: integer?` | 开始模式 `1002` 匹配；分数可省略 |
| `大厅服务 - 取消匹配` | 无 | 取消当前匹配 |
| `大厅服务 - 创建私人副本` | 无 | 创建允许中途加入的私人副本 |
| `大厅服务 - 启动多人私人副本` | 无 | 队长以当前队伍启动多人私人副本 |
| `大厅服务 - 加入口令副本` | `副本口令: string` | 通过口令加入私人副本 |
| `大厅服务 - 返回大厅` | 无 | 请求返回大厅实例 |
| `大厅服务 - 退出游戏` | 无 | 完成匹配清理，发送终态后退出游戏 |
| `大厅服务 - 发送队伍聊天` | `消息: string` | 向当前队伍发送聊天消息 |
| `大厅服务 - 发送世界聊天` | `消息: string` | 向世界频道发送聊天消息 |

队伍、匹配、副本切换和退出动作互斥；已有此类请求处理中时，新请求会立即拒绝。聊天请求单独串行。所有已受理请求默认在 10 秒后超时失败。

创建、加入和返回跨图实例时，当前运行环境不能跨地图保留请求状态。三项接口的立即结果在 `result_data.cross_map_tracking` 返回 `degraded`；`accepted = true` 只表示引擎请求已发出，不表示平台已经接受或客户端已经进入目标地图。返回大厅不会执行退出清理，队伍与 BOB 状态不会在请求提交时被主动删除。进入目标地图后应调用查询接口重新确认状态。

## 查询接口

除“获取状态快照”外，其余查询函数同步返回 ECA `TABLE`，不创建 `request_id`，也不触发终态事件。

### `大厅服务 - 获取状态快照`

立即返回请求受理结果；完成事件的 `result_data` 返回当前模式、连接、队伍、匹配和副本摘要：

`mode_id`、`mode_label`、`is_battle_context`、`bob_exists`、`bob_ready`、`aid`、`team_id`、`member_count`、`member_limit`、`is_captain`、`matching`、`launching`、`dungeon_token`、`result_event_id`、`result_event_name`。

### `大厅服务 - 获取队伍成员`

返回 `count`、`members_json`，以及最多 8 个展开成员字段：

`item_N_aid`、`item_N_name`、`item_N_state`、`item_N_score`、`item_N_is_captain`。

### `大厅服务 - 获取聊天记录`

返回 `count`、`chat_json`，以及最近 5 条展开记录：

`item_N_message`、`item_N_time`、`item_N_channel`、`item_N_sender_aid`、`item_N_sender_name`。

### `大厅服务 - 获取副本口令`

返回 `dungeon_token`。空字符串表示当前没有可用口令。

## ECA 函数与测试逻辑

上述 21 个正式函数已经生成到两张地图的 `global_trigger/function/` 目录，并保持相同的
`func_id`。可复用定义位于 `tools/eca/lobby_service_functions.json`；修改函数清单后，使用
项目内 `eca-json-builder/gen_function.py` 分别生成到 `EntryMap` 和 `MapName001`。

主关卡提供以下独立测试触发器，不会替换现有 E 键样本：

| 输入 | 测试内容 |
| --- | --- |
| F 键 | 调用 `大厅服务 - 创建队伍`，打印立即受理结果 |
| G 键 | 调用 `大厅服务 - 设置匹配分数(1000)`，打印立即受理结果 |
| H 键 | 调用 `大厅服务 - 获取状态快照`，打印立即受理结果，并由一次性子触发接收完成事件 |
| `大厅服务请求完成` | 打印所有动作的最终回调数据 |

测试定义位于 `tools/eca/lobby_service_tests.json`。F/G/H 的立即结果和完成事件是两次不同
输出，应通过其中的 `request_id` 判断是否属于同一个请求。

## 自定义事件配置

只需在项目主关卡中创建名为 `大厅服务请求完成` 的自定义事件，并配置一个名为 `回调数据` 的字典参数。子关卡自动使用主关卡的自定义事件配置，不需要重复创建；事件编号使用编辑器自动生成的值，不要手写或复制工程 JSON。

创建并保存事件后，建议触发 Y3 开发助手刷新 Lua 元数据，并确认运行时已生成该事件的 `register_custom_event_impl` 和 `CustomEventName` 映射。当前项目即使元数据尚未生成，也会使用从主关卡配置核对得到的正式编号作为后备，不影响 ECA 接收终态事件。

Lua 首选通过 `y3.eca.call` 按事件名称调用编辑器生成的实现；若名称通道失败，再优先读取 `y3.const.CustomEventName` 中的运行时编号，缺失时使用主关卡正式编号 `1876423410`，并按编辑器生成格式把终态 `TABLE` 封装到 `回调数据` 参数后通过 `y3.game.send_custom_event` 发送。`大厅服务 - 获取状态快照` 的 `result_event_id` 会返回最终采用的事件编号。
