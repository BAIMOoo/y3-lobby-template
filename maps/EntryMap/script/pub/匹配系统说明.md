# 基本原理

将地图分为 **大厅** 与 **游戏** 2部分。

这2部分可以是不同的地图，也可以是同一个地图的不同模式。

当前项目使用了后者方案，在编辑器中可以设置2个模式：

* `1001`: 大厅模式
* `1002`: 游戏模式

`dungeon.json` 请参考当前项目的配置，其中第一层的key为 `level_id` （`172371058548994502264384971909138463342`），请根据自己地图的 `*.gmp` 文件名修改

`match.json` 请参考当前项目的配置：

* `diffuse_time`: 匹配段位放宽时间（秒），到最后一个时间会立即开局
* `level_id`：匹配成功后切换到的地图id
* `game_mode`: 匹配成功后使用的游戏模式
* `sections`: 匹配段位规则
    * `max_score`: 当队伍中所有玩家的分数均不超过此分数时应用此规则
    * `min_player_num`: 最少的真人玩家数
* `teams`: 队伍数量

当匹配成功后会，客户端会自动加载新的地图并切换到 `1002` 模式。使用 `y3.game:get_current_game_mode()` 可以获取当前的游戏模式。

> 据说已经改了，下面2条可以不用看，仅供参考
> 需要注意的是，切换到新的地图后，在初始化事件中玩家还没有加入游戏。你需要通过“玩家-加入游戏”事件来初始化玩家的行为。
> 目前暂时没有办法知道玩家什么时候全部加入进来（不知道会有多少玩家进来，也不知道某个槽位是否被玩家占据），目前的解决办法是初始化后等待一段时间（10秒）再初始化，之后进不来的就不管了。

# 当前项目的流程

初始化时 `include 'pub.init'` 加载主逻辑，`pub.init` 会加载 `pub.core.bob` 与 `pub.pub`。

具体流程请查看 `pub.lua` 文件

## 初始化

首先通过 `玩家-加入游戏` 事件初始化玩家

+ 如果游戏模式是 `1001`： 启用大厅模式 `CreateBobInLobby`
+ 如果游戏模式是 `1002`： 启用游戏模式 `CreateBobInGame`

## 大厅模式

+ 创建匹配核心 `create_bob()`
    * 创建匹配核心对象 `New `Bob` ()`
    * 设置 `ip`、`port`，请参考当前项目 `pub.lua` 中 `configure_network` 的配置，在本地、QA服（`qa`）、测试服（`pre`）、正式服（`prod`）使用不同的设置
    * 设置 `game_play_id`，game_play_id是地图上传平台后生成的游戏id，上传地图且审核通过后后在审核后台查看，可咨询运营
    * 设置 `level_id`，这个从之前的 `dungeon.json` 里抄
    * 如果要单机测试，还需要伪造 `token`、`map_id`，map_id是地图上传平台后生成的版本id，上传地图且审核通过后在审核后台查看，可咨询运营
    ** token: 调试模式由 `pub/runtime_token.lua` 在运行时生成，并使用与 `BOB.aid` 相同的 aid；不同 aid 会影响世界聊天推送。**
+ 设置状态为大厅模式 `BOB:set_in_game(false)`
+ 注册登录成功后的回调函数 `BOB:event_on('准备就绪', function () ... end)`，当前项目会在登录成功后执行等待 BOB ready 的测试逻辑
+ 开始登录 `BOB:start()`

## 游戏模式

+ 创建匹配核心 `create_bob()`，同大厅模式
+ 设置状态为游戏模式 `BOB:set_in_game(true)`
+ 开始登录 `BOB:start()`

## 其它

当前项目导出了几个全局变量给ECA或测试逻辑使用：

+ 游戏模式打完后，ECA调用 `CreateBobInLobby()` 重建大厅模式，可以在不关游戏的情况下再次匹配
+ ECA调用 `SetScore` 修改玩家的分数，只要在开始匹配前调用即可
+ `ConnectVSCode()` 由于平台调试困难，预留了后门可以在平台上调试。可以查看《Y3开发助手》`readme.md` 中的 `远程终端` 章节。
+ 如果你的大厅和游戏是同一张地图，可以在大厅中调用 `关闭场景()` 来节省运算

# 主要接口

具体的界面逻辑都在 `ui.lua` 中，比较繁杂，这里挑几个重点：

+ 开始匹配 `BOB:start_match(game_mode, score)` ，需要传入目标游戏模式 `1002`。目前的接口只支持传游戏模式，如果你们的方案是匹配到不同的地图中，可以联系我扩展接口。
+ 匹配成功后，平台会负责切换地图，不需要地图内进行任何操作
    * 本地测试无法切换地图
+ 从匹配完成到进入游戏有几秒的时间，如果用户在这几秒内再次启用了匹配，那么会在之后再匹配成功一次从第一场对局中拉到第二场对局中，请务必在确认匹配完成后阻止再次进行匹配。
    * 本地禁止了用户在匹配过程中退出队伍、加入队伍、交换队长等操作。
+ 你也可以阅读 `bob.lua` ，看那些没有被标记为 `---@private` 的接口，上面都有完备的注释。
