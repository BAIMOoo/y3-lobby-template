# 完整 BOB 迁移

[上一篇：ECA 功能使用](./03-ECA功能使用.md) · [返回文档入口](./README.md) · [下一篇：轻量私人副本迁移](./05-轻量私人副本迁移.md)

本文用于把当前项目的完整大厅能力迁移到另一个 Y3 项目。完成后，目标项目可以按产品需要接入组队、匹配、世界/队伍聊天、多人私人副本，以及退出前的受控清理。

> **不要直接复用本文中的任何 ID、服务器地址、密钥或环境值。** 表格中的值只用于帮助你在当前项目中定位配置，全部属于“当前项目示例值”。迁移时必须从目标项目、目标环境和服务提供方取得真实值。

## 何时使用本方案

只要目标项目需要下列任一能力，就使用完整 `BOB` 迁移：

- 创建、加入、离开或管理队伍；
- 单人匹配、组队匹配或取消匹配；
- 世界聊天或队伍聊天；
- 以当前队伍启动多人私人副本；
- 退出前取消匹配、离队、删除服务端玩家状态并关闭连接。

这些能力共享连接、身份、玩家、队伍、请求状态和通知处理，不能按按钮或单个函数拆开复制。产品界面可以暂时不开放某项功能，但底层核心不能因为“当前没有按钮”而任意删减。

如果只需要创建引擎私人副本、分享口令、口令加入和返回大厅，请改用[轻量私人副本迁移](./05-轻量私人副本迁移.md)。轻量方案是手动提取或等价重写，不是完整核心的删文件版本。

## 三层迁移模型

| 层级 | 职责 | 本方案处理 |
| --- | --- | --- |
| 核心能力包 | 连接、身份、队伍、匹配、聊天、多人私人副本 RPC、退出清理 | 必须完整迁移，并在所有相关地图保持同一版本 |
| 调用适配 | Lua 对外调用接口，以及可选的 ECA 对外调用接口（正式函数） | `pub/pub.lua` 必须；ECA 路径按需保留 |
| 界面与验证 | 测试按钮、输入框、状态展示和图片资源 | 可选；正式 UI 不属于迁移内容 |

### 核心、适配与可选文件清单

以下路径中的 `maps/<大厅地图>` 和 `maps/<副本地图>` 指目标项目中实际承担大厅与匹配/私人副本的地图，不要求继续使用 `EntryMap` 或 `MapName001` 这两个名称。

#### 必须迁移：核心能力包

- 两张地图各自的 `script/pub/core/` 完整目录：
  - `bob.lua`
  - `network/coder.lua`
  - `network/fsm.lua`
  - `network/message_handler.lua`
  - `network/net_event.lua`
  - `network/protocol.lua`
  - `proto/proto_desc.lua`
  - `proto/proto_helper.lua`
  - `proto/service.pb`
  - `service/client.lua`
  - `service/define.lua`
- 两张地图各自的 `script/pub/runtime_token.lua`。
- 两张地图各自经过目标参数替换的 `script/pub/pub.lua`。
- 项目根目录的 `custom/protocol/protocol.pb`。
- 项目根目录配置 `gamemode.json`、`match.json`、`dungeon.json` 中与目标大厅、匹配和私人副本有关的条目。
- 两张地图各自的 `script/pub/init.lua`，以及各自 `script/main.lua` 中的 `include 'pub.init'`。

当前项目的两份 `pub/core/` 内容一致。迁移和以后升级时，应从同一份已确认版本同步到两张地图，不要维护两套不同核心。`pub/pub.lua`、`runtime_token.lua` 以及选择保留的适配层也应同步代码结构，只让明确的目标配置决定行为差异。

#### 条件迁移：ECA 路径适配层

- 保留 ECA 路径时：把 `pub/eca_lobby_api.lua` 同步到会调用 ECA 大厅函数的每张地图，并迁移 21 个正式 ECA 函数及主关卡完成事件配置。
- Lua-only 完整迁移时：不需要复制 `pub/eca_lobby_api.lua` 和正式 ECA 定义，并从每张地图的 `pub/init.lua` 删除 `include 'pub.eca_lobby_api'`。

`pub/eca_lobby_api.lua` 只是完整核心的 ECA 适配层，不是核心运行前提；但现有包含 21 个函数的对外调用接口依赖完整 `BOB`，不能把它当作无核心依赖的轻量模块。

#### 可选迁移：测试层

- 需要现成验收面板时，复制 `pub/test_ui.lua` 及它实际引用的测试 UI 图片资源，并保留 `include 'pub.test_ui'`。
- 使用目标项目自己的 UI 或暂不需要界面时，不复制 `pub/test_ui.lua`，并从每张地图的 `pub/init.lua` 删除 `include 'pub.test_ui'`。
- `pub/ui.lua` 当前不由 `pub.init` 默认加载，不在完整核心清单内。

测试 UI 只用于演示和验收，不是正式 UI 美术方案。移除测试 UI 不影响核心、Lua 对外调用接口或 ECA 对外调用接口。

#### 明确不要迁移

- `maps/MapName001/script/dungeon_unit_spawn.lua`。当前副本地图 `main.lua` 中，`include 'pub.init'` 属于大厅系统接入；紧随其后的 `include 'dungeon_unit_spawn'` 属于当前项目专属单位生成与中途加入初始化，不属于本迁移。
- 当前项目的战斗、单位、地形和玩法脚本。
- 外部配置器、正式 UI 美术、BOB 后端部署与协议开发、地图发布审核流程。

目标项目仍需自行实现玩家进入副本后的幂等初始化，包括中途加入场景；不要用当前项目的单位生成脚本代替目标项目逻辑。

## 迁移前准备

在修改目标项目之前完成以下记录：

1. 记录目标项目大厅地图、副本地图、关卡 ID、地图版本 ID、玩法固定 ID、模式 ID 和预期匹配人数。
2. 向服务维护方确认匹配环境、令牌主机、AES 密钥/IV、令牌有效期和协议文件版本。
3. 备份目标项目两张地图的 `main.lua`、现有 `pub/`、`custom/protocol/protocol.pb` 及三个根配置文件。
4. 记录目标项目原有启动结果；至少确认两张地图在迁移前能够正常加载。
5. 决定调用路径：Lua-only，或 Lua + ECA；再决定是否暂时保留测试 UI。

建议把备份作为每一阶段的回滚基线，不要等所有文件都覆盖后才第一次运行目标项目。

```lua
local player_field = {
    aid = tostring(player_aid),
    version = '2.0',
}
```

不要省略 `version`，不要写成数字 `2.0`。`custom/protocol/protocol.pb` 中该字段是协议的一部分，不能自行调整字段号或类型。

### 运行令牌

两张地图的 `pub/runtime_token.lua` 还包含 `TOKEN_KEY`、`TOKEN_IV`、`TOKEN_HOST` 和 `TOKEN_TTL`。当前仓库中的值只适用于当前测试环境，尤其不能复制其中的密钥、IV 和内网地址到其他项目。由服务维护方提供目标环境的值，并确认：

- AES 密钥和 IV 满足目标加密接口的长度要求；
- 主机地址能被目标环境识别；
- 有效期与服务端校验策略一致；
- 两张地图使用相同令牌规则。

不要把密钥写入文档、日志或提交说明；按目标项目已有的凭据管理方式保存。

### 根目录配置关系

三个根配置必须形成同一套关系：

| 文件 | 目标项目必须确认的关系 | 当前项目示例，仅用于理解 |
| --- | --- | --- |
| `gamemode.json` | 声明大厅、匹配和私人副本模式；`lobby` 符合平台约定 | `1001` 大厅、`1002` 匹配、`1003` 私人副本，`lobby = 0` |

### ECA 事件配置

仅在保留 ECA 路径时处理：

- 在目标项目主关卡创建自定义事件 `大厅服务请求完成`。
- 为事件添加字典/TABLE 参数 `回调数据`。
- 由目标编辑器保存并生成事件标识，再把目标事件信息接入 `pub/eca_lobby_api.lua`；不要直接复用当前项目的 `EVENT_ID = 1876423410`。
- 子关卡继承主关卡事件配置，不手工复制当前项目事件编号。
- 将正式 ECA 函数生成到实际使用它们的地图，并确认两张地图与同一份 DSL 契约一致。

## 分阶段迁移

每个阶段只在验收通过后进入下一阶段。失败时先按本阶段的回滚点恢复，不要带着未知错误继续叠加文件。

### 阶段 1：建立目录并复制协议

1. 在目标大厅地图和副本地图建立 `script/pub/`。
2. 把同一版本的完整 `pub/core/` 分别复制到两张地图。
3. 把同一版本的 `pub/runtime_token.lua`、`pub/pub.lua` 和 `pub/init.lua` 复制到两张地图。
4. 备份后替换目标根目录 `custom/protocol/protocol.pb`。
5. 比较两张地图的 `pub/core/`，确认相对路径集合和文件内容一致。

**阶段验收：** 所有必需文件存在；两份核心一致；没有复制 `dungeon_unit_spawn.lua`、测试 UI 或 ECA 层以外的项目专属脚本。

**回滚：** 删除本阶段新建的 `pub/`，恢复原协议文件。若目标项目原本已有同名模块，只恢复备份，不要整目录删除。

### 阶段 2：替换目标参数和根配置

1. 按配置替换表修改两张地图的 `pub/pub.lua`。
2. 在两张地图的 `pub/core/bob.lua` 同步替换目标私人副本模式常量。
3. 用目标凭据配置两份 `pub/runtime_token.lua`。
4. 修改 `gamemode.json`、`match.json` 和 `dungeon.json`，使模式、关卡、人数和私人副本能力互相一致。
5. 确认 `DungeonPlayerField.version = "2.0"`，并保留协议文件中对应字符串字段。

**阶段验收：** 全仓搜索当前项目示例 ID、`190356`、旧模式 ID、旧环境和旧令牌主机；迁移范围内不应再残留误用值。协议消息类型中的 `1001/1002` 是底层 RPC 常量，不要因为它与示例模式 ID 相同就盲目替换。

**回滚：** 恢复两张地图的 Lua 配置、三个根配置和协议备份。凭据配置错误时立即撤回，不要继续运行联网测试。

### 阶段 3：选择 Lua/ECA 和测试 UI 层

Lua-only 的两张地图使用：

```lua
include 'pub.core.bob'
include 'pub.pub'
```

Lua + ECA 的两张地图使用：

```lua
include 'pub.core.bob'
include 'pub.pub'
include 'pub.eca_lobby_api'
```

需要测试 UI 时，再在最后追加：

```lua
include 'pub.test_ui'
```

加载顺序不能倒置：ECA 和测试 UI 都依赖前面的核心与对外调用接口。Lua-only 必须删除 ECA `include`；不迁移测试 UI 必须删除测试 UI `include`，否则启动时会因为模块不存在而失败。

**阶段验收：** `pub/init.lua` 中每个 `include` 都有对应文件；ECA 方案的事件、正式函数与地图继承关系已配置；测试 UI 方案的资源引用均存在。

**回滚：** 恢复阶段前的 `pub/init.lua`；ECA 接线失败时先移除 ECA `include` 回到 Lua-only 核心验证；测试 UI 失败时停用 `include 'pub.test_ui'`，不要回滚核心。

### 阶段 4：接入两张地图入口

在目标大厅地图和目标副本地图的 `script/main.lua` 中，各加载一次：

```lua
include 'pub.init'
```

放在 Y3 基础运行环境已经可用、且业务代码开始调用大厅接口之前。当前项目中大厅地图入口位于 `maps/EntryMap/script/main.lua`，副本地图入口位于 `maps/MapName001/script/main.lua`；这些路径和行号不是目标项目要求。

副本地图不要复制当前项目紧随其后的：

```lua
include 'dungeon_unit_spawn'
```

目标项目应在自己的玩家加入与中途加入流程中调用幂等初始化逻辑，避免同一玩家重复创建单位或重复发放资源。

**阶段验收：** 两张地图都能启动；日志中没有模块缺失、协议加载失败或重复初始化；两张地图只加载一次 `pub.init`。

**回滚：** 从两张 `main.lua` 恢复原入口或暂时移除 `include 'pub.init'`，保留已复制文件以便定位。

### 阶段 5：验证连接与状态查询

1. 在真实平台进入大厅地图，确认创建大厅连接并收到“准备就绪”。
2. 查询状态，确认连接存在、已就绪、AID 和当前模式正确。
3. 跨入副本地图后确认重新加载 `pub.init`，建立副本上下文连接，再重新查询状态。
4. ECA 路径额外确认异步状态快照以 `request_id` 关联 `大厅服务请求完成`，不把受理结果当最终结果。

**阶段验收：** 大厅和副本两种上下文都能独立就绪；跨图后取得的是目标地图的新状态，不沿用旧 Lua 运行环境。

**回滚：** 恢复入口、玩法 ID、环境和令牌配置；连接未稳定前不要测试队伍或匹配。

### 阶段 6：验证队伍与聊天

使用两个真实客户端验证：

1. 客户端 A 创建队伍，客户端 B 通过队伍编号加入。
2. 查询成员，确认双方看到一致的队长、人数和成员 AID。
3. 验证队伍聊天只在队伍上下文可用。
4. 验证世界聊天在连接就绪后可发送、接收。
5. 验证离队；再验证队长权限相关操作至少一种，如转移队长、移出成员或解散队伍。

**阶段验收：** 成员状态在两端一致；世界/队伍频道没有串线；无权限操作被明确拒绝，不造成状态卡死。

**回滚：** 使用受控退出清理测试账号状态；恢复上阶段配置。不要通过删除某个聊天或队伍核心文件规避问题。

### 阶段 7：验证匹配

1. 分别验证单人或产品要求的组队匹配入口。
2. 确认 `match.json` 的模式、目标关卡、人数和分数段与 Lua 参数一致。
3. 发起匹配后确认状态变为匹配中，再验证取消匹配能恢复空闲。
4. 再次匹配并等待成功跨图；进入目标地图后重新查询模式和连接状态。

**阶段验收：** 匹配开始、取消和成功跨图形成闭环；组队匹配只能由符合权限的玩家控制；跨图后状态属于目标地图。

**回滚：** 先取消匹配并受控退出，再恢复 `match.json`、模式/关卡/人数常量和入口。服务环境不可用时不要改核心网络协议绕过错误。

### 阶段 8：验证多人私人副本

1. 由两个客户端组成满足人数要求的队伍，确认发起者是队长。
2. 启动多人私人副本，并检查提交的每个玩家项均包含字符串 `aid` 与 `version = "2.0"`。
3. 等待平台跨图；进入目标副本地图后重新查询状态和副本口令。
4. 按产品需要验证口令加入、中途加入限制和返回大厅。

**阶段验收：** 队伍成员进入同一私人副本；协议未因缺失 `version` 被拒绝；补人时间、容量和模式符合 `dungeon.json`。

**回滚：** 返回大厅或受控退出，恢复 `dungeon.json`、私人副本模式、人数及协议文件。协议版本不匹配时恢复整套已验证协议，不要只改 Lua 字段掩盖问题。

### 阶段 9：验证受控退出清理

分别在空闲、队伍中和匹配中触发完整路径的受控退出入口。该入口应按顺序尽力取消匹配、离开队伍、删除服务端玩家状态、关闭客户端，再退出游戏。

返回大厅是跨图操作，不等于退出，不能用它代替退出清理。引擎强制关闭事件也不能阻塞等待清理，因此产品退出按钮必须调用受控入口，例如 Lua 路径的 `MatchTestExitGame` 或 ECA 路径的 `大厅服务 - 退出游戏`。

**阶段验收：** 重进游戏后测试账号没有残留匹配或队伍状态；清理步骤失败时有明确日志，并且退出流程不会无限等待。

**回滚：** 恢复产品退出按钮原接线和入口备份。若测试 UI 已完成使命，可直接删除 `include 'pub.test_ui'` 并移除其资源，不需要回滚核心。

## 最终验收清单

- [ ] 两张地图都通过 `include 'pub.init'` 接入，且各加载一次。
- [ ] 两份 `pub/core/` 文件集合和内容一致。
- [ ] `pub/runtime_token.lua`、参数化后的 `pub/pub.lua`、根协议和三个根配置已迁移。
- [ ] 所有当前项目示例 ID、环境、地址和凭据均已替换，未被当作通用默认值。
- [ ] `DungeonPlayerField.version` 是必填字符串，当前固定为 `"2.0"`。
- [ ] Lua-only 已删除 ECA `include`；ECA 路径已配置正式函数和完成事件。
- [ ] 不使用测试 UI 时已删除 `include 'pub.test_ui'`；使用时资源完整。
- [ ] 没有迁移 `dungeon_unit_spawn.lua` 或当前项目专属战斗/单位逻辑。
- [ ] 连接、状态查询、队伍、聊天、匹配、多人私人副本和受控退出均按阶段验收。
- [ ] 双客户端、真实平台和跨地图验证有记录；跨图后均重新查询状态。

更完整的自动检查命令、双客户端记录模板和故障定位见[验证与故障排查](./06-验证与故障排查.md)。

## 整体回滚顺序

若最终集成无法继续，按与迁移相反的顺序回滚：

1. 停用并移除测试 UI `include` 和测试资源。
2. 恢复两张地图原有 `main.lua` 与 `pub/init.lua`，先切断大厅系统入口。
3. 恢复 `gamemode.json`、`match.json`、`dungeon.json`。
4. 恢复原 `custom/protocol/protocol.pb`。
5. 恢复或移除本次迁入的 `pub/` 文件。
6. 使用迁移前基线重新启动两张地图，确认回滚没有留下模块引用。

不要只恢复协议文件而保留新核心，也不要只恢复模式配置而保留指向新模式的 Lua 常量。回滚必须以同一阶段的文件集合为单位。
