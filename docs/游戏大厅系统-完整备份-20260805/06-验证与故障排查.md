# 验证与故障排查

[返回文档入口](./README.md)

本章用于迁移或接入后的验收。请保留每一步的时间、客户端、地图、操作、请求编号、日志和实际结果；发生失败时，不要跳过当前层继续验证下一层。

本地自动化只能证明文档、ECA 定义和 Lua 适配契约在仓库内一致，不能证明平台登录、匹配、聊天、私人副本或退出清理在真实服务上成功。真实平台项尚未执行时，验收记录必须写“未验证”，不能写“已通过”。

## 验证顺序

1. 完成静态检查，排除缺文件、无效链接、示例语法和 ECA 契约错误。
2. 完成本地运行检查，确认地图入口加载、连接初始化和请求日志符合预期。
3. 在真实平台检查身份、服务连接和单客户端流程。
4. 使用两个独立客户端检查队伍、聊天、口令加入和多人流程。
5. 完成大厅到副本、口令中途加入、副本到大厅的跨地图检查。
6. 按所选迁移路线逐项签核，不适用项标记为“不适用”并写明原因。

## 一、静态检查

在项目根目录执行：

```powershell
py -3 tests/documentation_examples_test.py
py -3 tests/eca_lobby_eca_json_test.py
lua tests/eca_lobby_api_contract_test.lua
py -3 -m py_compile tests/documentation_examples_test.py
```

四个命令分别检查：

- 文档文件、双向导航、本地链接、fenced JSON 解析、Lua 示例语法、Python 3.8 语法、关键引擎 API 和文件末尾换行。
- 两张地图的正式 ECA JSON、21 个函数和 Lua 注册的一致性。
- ECA 立即结果、完成事件、异步请求和跨图降级契约。
- 测试脚本能被当前 Python 3 编译器完整编译。

全部命令退出码为 0 才算静态检查通过。若本机没有 `lua`，应记录“Lua 解释器缺失，契约测试未执行”，安装可用 Lua 后补跑；不能把缺少运行环境记为通过。

同时人工确认：

- 大厅与副本地图入口都加载 `include 'pub.init'`。
- 完整路线中 `pub.init` 加载 `pub.core.bob` 与 `pub.pub`；保留 ECA 时加载 `pub.eca_lobby_api`。
- `pub.test_ui` 只在需要演示面板时加载，不把 `pub/ui.lua` 当作默认核心。
- 目标项目已替换玩法 ID、地图/关卡 ID、模式 ID、环境、人数和协议相关示例值。
- `gamemode.json`、`match.json`、`dungeon.json` 的模式和目标关卡能互相对应。

## 二、本地运行检查

本地运行用于发现加载、参数、事件接线和状态机问题，不用于证明真实平台行为。

| 步骤 | 操作与观察点 | 本地预期结果 | 失败时先检查 |
| --- | --- | --- | --- |
| 1 | 分别启动大厅地图与副本地图，观察脚本加载日志 | `pub.init` 及所选 Lua/ECA 层无加载错误 | 两张地图的 `main.lua`、模块相对路径、是否维护了两套不同核心 |
| 2 | 触发本地玩家加入，记录当前模式和建连入口 | 大厅调用 `CreateBobInLobby`，副本模式调用 `CreateBobInGame`，且每名玩家只初始化一次 | 模式 ID、重复事件注册、已有玩家初始化入口 |
| 3 | Lua 路径观察“准备就绪”及状态日志；ECA 路径调用 `大厅服务 - 重建大厅连接` | 能看见明确的受理、拒绝或连接错误，不出现静默卡住 | 身份来源、环境、`game_play_id`、运行令牌、服务地址 |
| 4 | ECA 调用 `大厅服务 - 获取状态快照` | 立即得到 `accepted`/`request_id`，随后从 `大厅服务请求完成` 收到对应结果 | 自定义事件名、参数名 `回调数据`、`request_id` 保存与比较逻辑 |
| 5 | 故意传入空口令或在操作锁占用时重复操作 | 请求立即 `accepted = false`，显示 `reason`，且不等待完成事件 | 输入规范化、按钮禁用、操作锁和拒绝分支 |

`大厅服务 - 获取状态快照` 是请求式异步，不是同步读取：调用时先返回受理结果；仅当 `accepted = true` 时保存 `request_id` 并等待一次 `大厅服务请求完成`。`accepted = false` 不会再产生完成事件。

## 三、真实平台检查

使用已发布到测试环境的目标项目和真实平台账号。先完成单客户端基线：

- 登录后记录 AID、`game_play_id`、环境、当前地图和模式。
- 等待大厅连接就绪，再请求一次状态快照或读取 Lua 状态。
- 发送一条世界聊天，确认发送回调与聊天记录更新。
- 发起单人匹配，确认进入排队；取消后确认匹配状态恢复。
- 再次发起匹配并等待平台匹配成功与切图。
- 从副本返回大厅，确认大厅入口重新加载并重新建立连接。
- 最后走受控退出入口，记录取消匹配、离队、删除玩家状态和关闭连接的结果。

真实平台验证通过的最低证据是：操作时间、账号/AID、环境、目标模式、请求或事件结果、切图前后地图，以及必要的日志或截图。只有按钮提示“请求成功”不足以证明平台最终状态。

## 四、双客户端检查

客户端 A 与 B 必须使用两个独立的真实平台身份，不能用同一账号的本地模拟替代。

1. A 创建队伍，B 使用队伍编号加入；两端成员列表、队长和人数一致。
2. B 尝试队长专属操作，应被拒绝；A 转移队长后，权限随新队长变化。
3. A、B 分别发送队伍聊天；两端均看到正确发送者、内容和顺序。
4. 由当前队长开始组队匹配，再取消一次；两端匹配状态一致。
5. 满足人数后由队长启动多人私人副本；两端都完成跨图并在目标地图重新查询状态。
6. 另起一轮：A 创建可中途加入的引擎私人副本并读取非空口令，B 留在大厅用该口令加入。
7. 任一客户端返回大厅，确认只改变该客户端所在上下文，并在大厅重新查询状态。

每一步都记录两端结果。只观察 A 端不能证明 B 已收到队伍通知、聊天或跨图结果。

## 五、跨地图检查

创建私人副本、加入口令副本和返回大厅会销毁旧地图的 Lua 运行环境。ECA 结果中的 `cross_map_tracking = 'degraded'` 只表示当前适配层不能跨地图持续跟踪；它不等于失败，也不证明已经进入目标地图。

| 场景 | 切图前记录 | 目标地图观察点 | 预期结果 |
| --- | --- | --- | --- |
| 大厅创建私人副本 | 请求结果、目标模式、AID | 新地图入口加载、当前模式、副本 `space_id`/口令 | 进入副本模式，重新查询得到当前副本信息 |
| 大厅口令加入 | 实际口令、加入时间、请求结果 | `data.is_middle_join`、幂等初始化次数、当前副本口令 | B 进入与 A 相同副本，每名中途加入玩家只初始化一次 |
| 多人私人副本 | 队长、人数、每名玩家 `version` | 两端目标地图、连接重建、队伍/副本状态 | 两端进入目标地图，`version` 为字符串 `"2.0"` |
| 副本返回大厅 | 返回请求结果、旧副本信息 | 大厅入口加载、连接就绪、重新查询状态 | 进入大厅模式，不继续使用旧 `BOB`、旧 `space_id` 或旧请求状态 |

跨图请求出现成功完成事件时，只能记录“平台已受理切图”。必须等目标地图的玩家加入事件发生，并在新运行环境重新查询模式、连接和副本信息，才能记录“已进入目标地图”。

## 六、按迁移路线签核

### 完整 BOB 路线

- [ ] 两张地图使用同一份 `pub/core/`、参数化的 `pub/pub.lua` 和 `pub/runtime_token.lua`。
- [ ] 协议文件、地图入口、根目录配置及玩法/模式/关卡关系均已迁移并替换。
- [ ] Lua-only 路线已移除不需要的 `include 'pub.eca_lobby_api'`；ECA 路线已保留适配层和正式函数。
- [ ] 不需要测试 UI 时已移除 `include 'pub.test_ui'`；需要时已迁移其资源。
- [ ] 大厅/副本连接与状态查询通过。
- [ ] 创建、加入、离开、队长权限和人数同步通过。
- [ ] 世界聊天与双客户端队伍聊天通过。
- [ ] 单人/组队匹配、取消和匹配成功切图通过。
- [ ] 多人私人副本的队长、人数、`version = "2.0"` 与跨图通过。
- [ ] 返回大厅与受控退出清理通过。

完整路线的底层核心需保持完整；产品 UI 可以不开放某些功能，但不能据此删除共享连接、通知或清理模块。

### 轻量私人副本路线

- [ ] 已明确这是手动提取或等价重写，不是复制完整 `BOB` 后删文件。
- [ ] 未迁移 `pub/core/`、`runtime_token.lua`、协议文件、队伍、匹配、聊天和 `BOB` 退出清理。
- [ ] 已实现上下文判断、副本信息读取、口令规范化和 `space_id` 读取。
- [ ] 已实现创建可加入私人副本、口令加入、创建大厅实例并返回。
- [ ] `dungeon.json` 已启用私人副本，并正确配置容量与 `can_add_in_time`。
- [ ] 使用轻量 ECA 对外调用接口时只暴露私人副本子集，没有复制依赖 `BOB`、包含 21 个函数的完整对外调用接口。
- [ ] A 创建副本并获取口令、B 使用口令加入、任一端返回大厅的五步闭环通过。
- [ ] 跨图后重新查询状态，中途加入调用目标项目自己的幂等初始化钩子且仅执行一次。

轻量路线不验收队伍、匹配、聊天、多人私人副本或完整 `BOB` 受控退出；需要其中任一能力时，应改用完整路线。

## 本地自动化不能证明的项目

下表每项都必须在真实平台人工执行。未执行时填写“未验证”。

| 人工项目 | 观察点 | 预期结果 | 失败时优先检查 |
| --- | --- | --- | --- |
| 平台令牌与 `game_play_id` | 登录请求使用的 AID、令牌、玩法 ID、环境，连接完成或错误事件 | 真实身份授权成功，连接进入就绪状态 | `pub.runtime_token`/平台令牌来源、AID 是否一致、目标项目 `game_play_id`、环境 |
| 真实匹配 | 开始请求、排队状态、取消结果、匹配成功通知、目标模式与切图 | 平台接受排队；取消可恢复；成功后进入匹配目标地图 | `match.json` 的 `game_mode`/`level_id`/人数/队伍配置、环境、队长权限、服务可用性 |
| 双客户端队伍聊天 | A/B 队伍编号、成员、发送者、内容、到达顺序 | 两端在同一队伍并看到相同的队伍消息 | 连接就绪、是否同队、聊天回调、订阅/通知、两端 AID |
| 多人私人副本 | 当前队长、人数、每名玩家 `aid` 与 `version`、两端目标地图 | 队长发起后所有成员进入同一目标副本 | 完整 `BOB`、队长权限、最低/最高人数、`version` 是否字符串 `"2.0"`、地图/关卡 ID |
| 口令中途加入 | A 的当前 `space_id`、B 提交的口令、加入时间、`data.is_middle_join`、初始化次数 | B 在允许时间内进入 A 的副本，幂等初始化只执行一次 | 口令是否来自目标副本、B 是否仍在大厅、`can_add_in_time`、容量、中途加入钩子 |
| `can_add_in_time`、满房、无效口令 | 分别在超时、达到容量和伪造口令时提交，记录平台提示、运行日志与客户端实际上下文 | 三种请求均被平台拒绝，客户端保留在原上下文且能继续操作 | `dungeon.json` 的可加入时间/容量/私人副本开关、口令规范化；轻量路线不能从本地 `reason` 推导平台最终原因，完整路线按其错误或完成事件取证 |
| 受控退出 | 退出前匹配/队伍状态，取消匹配、离队、删除玩家状态、连接关闭日志，重登后状态 | 清理按顺序执行并退出；重登不残留旧匹配或队伍状态 | 是否调用 `MatchTestExitGame`/正式退出函数、操作锁、清理超时、服务通知、是否被强制退出绕过 |

## 故障定位表

下表中的 `request_id` 和完成事件用于完整 `BOB`/正式 ECA 路线。轻量路线的 `accepted`、`reason` 和 `cross_map_tracking` 只描述本地调用与追踪能力；平台最终失败要结合平台提示、运行日志、客户端是否留在原上下文以及跨图后重新查询定位。

| 现象 | 判断依据 | 优先检查 | 修复后复测 |
| --- | --- | --- | --- |
| 无法连接或一直未就绪 | 没有“准备就绪”，或连接错误/超时 | AID 与令牌一致性、`game_play_id`、环境、服务地址、是否重复创建 `BOB` | 重建连接并请求状态快照 |
| 立即返回 `accepted = false` | 返回中有 `reason`，`request_id` 为空 | 参数类型/空值、连接前置、队伍/匹配/启动状态、操作锁、是否正在退出 | 修正前置条件后重发；不要等待旧请求完成事件 |
| `accepted = true` 但收不到异步事件 | 已保存 `request_id`，10 秒内无匹配事件 | 主关卡事件 `大厅服务请求完成`、参数 `回调数据`、子关卡继承、监听注册时机、请求编号比较 | 发起单个状态快照并确认只收到一次匹配事件 |
| `cross_map_tracking = 'degraded'` | 创建/加入/返回的结果数据含该字段 | 不把它当作到图确认；检查平台是否已受理、目标地图入口及玩家加入事件 | 在目标地图重新请求状态快照或读取口令 |
| 多人私人副本被拒绝 | 原因指向权限、人数或字段 | 当前玩家是否队长、人数是否满足配置、每名玩家 `aid`、`version` 是否字符串 `"2.0"` | 保持同队并由队长重新发起，核对两端切图 |
| 口令加入失败 | 本地前置拒绝，或平台提示/日志显示最终失败，客户端仍在原上下文 | B 是否在大厅、口令是否来自当前 `space_id`、规范化结果、`enable_private`、`can_add_in_time`、容量；区分本地 `reason` 与平台证据 | 使用新建副本的新口令在允许时间内重试，并按所选路线重新记录结果 |
| 匹配或私人副本进入错误地图 | 请求成功但目标模式/地图不符 | 玩法 ID、`gamemode.json`、`match.json`、`dungeon.json` 中模式与关卡 ID 的对应关系 | 重新发布测试配置并记录切图前后模式 |
| 跨图后仍显示旧状态 | UI 保留旧队伍、模式、口令或请求 | 是否在新地图重载入口、重建连接、清空旧请求/UI 状态并重新查询 | 在目标地图创建全新快照，核对当前模式和 `space_id` |
| 中途加入重复生成或未初始化 | 同一玩家初始化次数不是 1 | `data.is_middle_join` 分支、目标项目幂等标记、初始化钩子是否被多个入口调用 | 同一口令再次进行双客户端中途加入测试 |
| 退出后残留匹配/队伍状态 | 重登仍在旧状态，或清理日志缺步骤 | 是否走受控退出、取消匹配/离队/删除状态顺序、超时处理、强制退出路径 | 重登核对状态，再进行一次正常受控退出 |

## 验收记录模板

每次验证至少记录：

| 字段 | 内容 |
| --- | --- |
| 路线 | 完整 `BOB` / 轻量私人副本 |
| 调用方式 | Lua / ECA |
| 版本与环境 | 项目版本、平台测试环境、配置版本 |
| 客户端 | A/B 的账号或 AID，不记录完整令牌 |
| 场景 | 静态、本地、真实平台、双客户端或跨地图 |
| 操作 | 函数/按钮、参数、请求时间 |
| 关联信息 | `request_id`、地图、模式、队伍编号或口令脱敏值 |
| 结果 | 通过 / 失败 / 未验证 / 不适用 |
| 证据 | 日志、截图或录像位置 |
| 失败定位 | 对应故障表项、原因与复测结果 |

最终签核要求四个静态命令全部通过，所选路线清单完成，适用的真实平台、双客户端和跨地图项目有证据。任何未执行的平台项都必须保留为“未验证”，不得由本地测试结果代替。
