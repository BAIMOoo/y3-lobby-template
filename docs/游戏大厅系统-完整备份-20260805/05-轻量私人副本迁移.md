# 轻量私人副本迁移

[返回文档入口](./README.md)

> 本路线是面向熟悉 Y3 项目结构的开发者的高级手动提取方案。它要求按职责重写或提取最小模块，**不是整目录复制**，也不是从完整 `BOB` 中随意删除文件后继续运行。

## 适用边界

只有在目标项目仅需要以下闭环时选择本路线：

1. 在大厅创建一个允许另一名玩家中途加入的私人副本。
2. 进入副本后读取并分享副本口令。
3. 另一名玩家在允许补人的时间内使用口令加入。
4. 副本中的玩家创建大厅实例并返回大厅。
5. 每次跨图结束后，在新地图重新查询当前状态。

如果还需要队伍、匹配、世界聊天、队伍聊天或多人私人副本，请选择[完整 `BOB` 迁移](./04-完整BOB迁移.md)。这些能力共享完整核心，不能用本章的轻量模块替代。

## 需要实现的职责

目标项目需要自行实现下列职责。迁移时按职责核对，不按当前项目目录核对。

| 职责 | 最小要求 |
| --- | --- |
| 读取副本信息 | 调用 `GameAPI.get_dungeon_info()`，允许其返回空值 |
| 规范化口令 | 把 `space_id` 转为字符串并去除首尾空白；空值统一为 `''` |
| 判断当前上下文 | 大厅模式允许创建和口令加入；副本上下文拒绝重复创建或加入 |
| 创建可加入私人副本 | 使用目标副本关卡、私人模式和大于 1 的总容量发起创建 |
| 获取副本口令 | 跨图进入副本后读取 `GameAPI.get_dungeon_info().space_id` |
| 通过口令加入 | 在大厅校验非空口令后发起加入请求 |
| 返回大厅 | 创建大厅关卡的单人 `1001` 实例，而不是在当前副本内切换关卡 |
| 跨图后重新查询 | 新地图加载完成后重新读取模式和副本信息，不保留旧对象引用 |
| 初始化加入玩家 | 在目标项目自己的“玩家-加入游戏”入口调用幂等初始化钩子，同时覆盖首批进入和中途加入 |

## 明确不迁移的内容

轻量路线不迁移以下文件或能力：

- `maps/*/script/pub/core/`。
- `pub/runtime_token.lua`。
- `custom/protocol/protocol.pb`。
- 队伍、匹配、世界聊天、队伍聊天和多人私人副本。
- `BOB` 登录、通知、请求状态与退出清理。
- 当前依赖完整 `BOB` 的 `pub/eca_lobby_api.lua` 及其 **21 个正式函数**。
- `pub/test_ui.lua`、测试图片以及当前项目的正式或测试界面布局。
- 当前项目的战斗、单位生成、地形和玩法初始化实现。

这里不包含 `BOB` 退出清理并不表示可以复制其一部分清理代码。轻量模块没有创建对应的服务端队伍、匹配或聊天状态，因此只负责私人副本切换；项目自身的退出流程仍由目标项目维护。

## 仍需配置的项目项

代码接线前，先在目标项目已有的配置文件中建立一致关系。

| 配置项 | 当前项目示例 | 目标项目要求 |
| --- | --- | --- |
| 大厅关卡 | `EntryMap` 对应关卡 UUID | 替换为目标大厅关卡 UUID |
| 副本关卡 | `MapName001` 对应关卡 UUID | 替换为目标副本关卡 UUID，不能仍指向大厅 |
| 大厅模式 | `1001` | 若目标项目采用不同模式，代码与配置必须同时替换 |
| 私人副本模式 | `1003` | 若目标项目采用不同模式，代码与配置必须同时替换 |
| 私人副本容量 | `2` | 至少为 2；该值是房间总容量，不是可追加人数 |
| `enable_private` | `1` | 目标副本关卡和模式必须允许私人副本 |
| `max_player_num` | 当前配置为 `8` | 不得小于代码传入的房间总容量 |
| `can_add_in_time` | 当前副本模式为 `120` | 设置允许口令中途加入的时间窗，并用真实双客户端验证 |
| 玩家初始化 | 当前项目有自己的示例逻辑 | 接入目标项目现有的幂等玩家初始化钩子，不复制当前项目玩法逻辑 |

`can_add_in_time` 控制副本开始后仍允许补人的时间。即使时间窗尚未结束，创建时把最大人数传成 `1` 也会使创建者立即占满房间；因此双人轻量闭环必须创建容量为 `2` 的房间。超过时间窗、房间已满或口令无效时，应保留平台拒绝结果，不要在 Lua 中绕过限制。

## 引擎接口与参数

下列调用是本路线的核心边界。示例中的 `level_id` 和 `lobby_level_id` 必须替换为目标项目的关卡 UUID。

| 操作 | 引擎调用 | 说明 |
| --- | --- | --- |
| 创建可加入私人副本 | `request_create_private_dungeon(level_id, 1003, 2)` | `1003` 是当前项目私人模式示例，`2` 是总容量 |
| 读取当前口令 | `GameAPI.get_dungeon_info().space_id` | 只在副本地图加载后读取，并处理副本信息为空的情况 |
| 口令加入 | `request_join_private_dungeon(token)` | `token` 必须规范化且非空 |
| 返回大厅 | `request_create_private_dungeon(lobby_level_id, 1001, 1)` | 创建单人大厅实例并跨图；不能用当前副本内的关卡切换代替 |

## 最小 Lua 实现

在大厅地图和副本地图的有效脚本根目录分别放置同一份小型模块，例如 `maps/<地图>/script/private_dungeon.lua`。两张地图应保持该模块一致，但不要复制 `pub/` 或其他目录。

```lua
local M = {}

local LOBBY_GAME_MODE = 1001
local PRIVATE_GAME_MODE = 1003

local function normalize_token(token)
    return tostring(token or ''):match('^%s*(.-)%s*$')
end

local function get_dungeon_info()
    if GameAPI.get_dungeon_info then
        return GameAPI.get_dungeon_info()
    end
    return nil
end

local function get_current_mode(info)
    local mode
    if y3.game.get_current_game_mode then
        mode = y3.game.get_current_game_mode()
    end
    if (not mode or tostring(mode) == '0') and info then
        mode = info.game_mode
    end
    return math.tointeger(mode) or mode or 0
end

local function request_with_local_player(callback)
    local requested = false
    y3.player.with_local(function(player)
        requested = true
        callback(player.handle)
    end)
    if not requested then
        return false, '未找到本地玩家'
    end
    return true
end

function M.is_battle_context()
    local info = get_dungeon_info()
    local mode = get_current_mode(info)
    return mode ~= 0 and mode ~= LOBBY_GAME_MODE
end

function M.get_state()
    local info = get_dungeon_info()
    return {
        mode_id = get_current_mode(info),
        is_battle_context = M.is_battle_context(),
        dungeon_token = normalize_token(info and info.space_id),
    }
end

function M.create_private_dungeon(level_id)
    if M.is_battle_context() then
        return false, '当前已在副本中'
    end
    return request_with_local_player(function(role)
        role:request_create_private_dungeon(level_id, 1003, 2)
    end)
end

function M.get_dungeon_token()
    local info = get_dungeon_info()
    return normalize_token(info and info.space_id)
end

function M.join_private_dungeon(token)
    token = normalize_token(token)
    if token == '' then
        return false, '请输入副本口令'
    end
    if M.is_battle_context() then
        return false, '当前已在副本中'
    end
    return request_with_local_player(function(role)
        role:request_join_private_dungeon(token)
    end)
end

function M.return_lobby(lobby_level_id)
    return request_with_local_player(function(role)
        role:request_create_private_dungeon(lobby_level_id, 1001, 1)
    end)
end

M.LOBBY_GAME_MODE = LOBBY_GAME_MODE
M.PRIVATE_GAME_MODE = PRIVATE_GAME_MODE

return M
```

如果目标项目不使用当前示例模式 `1001` 和 `1003`，必须同时修改模块常量、两个引擎调用参数和项目配置，不能只改其中一处。

### 返回契约分三层

| 层 | 返回或证据 | 准确含义 |
| --- | --- | --- |
| Lua 模块 | `boolean, reason?` | `true` 只表示已找到本地玩家并调用了引擎接口；`false` 和 `reason` 只描述空口令、上下文不符或没有本地玩家等本地前置失败 |
| 薄 ECA | ECA `TABLE` 中的 `accepted`、`reason`、`cross_map_tracking` | 把 Lua 模块的本地结果包装成 ECA 可用结构；`accepted = true` 仍不代表平台最终接受 |
| 平台最终结果 | 实际跨图状态、平台提示、运行日志，以及目标地图重新查询 | 用于证明最终成功，或记录时间窗、容量、口令状态等平台最终拒绝原因 |

`request_create_private_dungeon` 和 `request_join_private_dungeon` 当前没有最终结果回调。因此，无论 Lua 返回 `true`，还是薄 ECA 返回 `accepted = true`，都不能从本地 `reason` 推导平台最终结果。

### 入口接线

在大厅和副本地图各自已有的地图入口中加载模块。当前项目存在 `maps/<地图>/script/y3/`，因此 `include` 从该地图的 `script/` 根目录解析，不添加 `script.` 前缀。

```lua
local PrivateDungeon = include 'private_dungeon'
```

实际地图入口通常还会加载其他模块，不要为了接入轻量模块覆盖原入口。只增加一次 `include`，并把返回的模块传给目标项目自己的 UI、ECA 对外调用接口和玩家初始化代码。

## 轻量 ECA 对外调用接口

不要复制 `pub/eca_lobby_api.lua`。该文件还注册队伍、匹配、聊天、多人私人副本、退出清理和完整状态查询，是依赖 `BOB` 的 21 函数适配层。轻量 ECA 只注册下列五个项目内函数，并直接委托给前述 Lua 模块。

大厅地图和副本地图都必须加载这份轻量 ECA 对外调用接口，目标项目也只为这五个名称建立可见 ECA 函数定义。这样跨图后的新地图才能执行“获取副本口令”和“重新查询状态”。函数定义由目标项目编辑器生成并保存，不复制当前项目 21 个函数的 JSON 或函数编号。

| 五步 | 建议正式名 | 委托 | 返回与后续动作 |
| --- | --- | --- | --- |
| 1. 创建私人副本 | `轻量副本 - 创建私人副本` | `create_private_dungeon(level_id)` | Lua 返回 `true` 后，薄 ECA 返回 `accepted = true` 和 `cross_map_tracking = 'degraded'`；等待跨图 |
| 2. 获取副本口令 | `轻量副本 - 获取副本口令` | `get_dungeon_token()` | 在副本地图同步返回 `dungeon_token`，空串表示尚无口令 |
| 3. 口令加入 | `轻量副本 - 加入口令副本` | `join_private_dungeon(token)` | Lua 本地调用成功后由薄 ECA 返回 `accepted = true`；平台仍可因时间窗、容量或口令拒绝 |
| 4. 返回大厅 | `轻量副本 - 返回大厅` | `return_lobby(lobby_level_id)` | Lua 本地调用成功后由薄 ECA 返回 `accepted = true`，随后等待跨图 |
| 5. 跨图后重新查询 | `轻量副本 - 重新查询状态` | `get_state()` | 在新地图重新读取 `mode_id`、`is_battle_context` 和 `dungeon_token` |

下面是可直接作为目标项目轻量 ECA 对外调用接口起点的 Lua 注册代码。关卡 UUID 是目标项目参数，不是当前项目的通用值。

```lua
local PrivateDungeon = include 'private_dungeon'

local DUNGEON_LEVEL_ID = '替换为目标副本关卡UUID'
local LOBBY_LEVEL_ID = '替换为目标大厅关卡UUID'

local function action_result(action, accepted, reason, crosses_map)
    return {
        accepted = accepted == true,
        reason = tostring(reason or ''),
        action = action,
        cross_map_tracking = crosses_map and 'degraded' or '',
    }
end

local function create_private_dungeon()
    local accepted, reason = PrivateDungeon.create_private_dungeon(DUNGEON_LEVEL_ID)
    return action_result('创建私人副本', accepted, reason, accepted)
end

local function get_dungeon_token()
    return {
        dungeon_token = PrivateDungeon.get_dungeon_token(),
    }
end

local function join_private_dungeon(token)
    local accepted, reason = PrivateDungeon.join_private_dungeon(token)
    return action_result('加入口令副本', accepted, reason, accepted)
end

local function return_lobby()
    local accepted, reason = PrivateDungeon.return_lobby(LOBBY_LEVEL_ID)
    return action_result('返回大厅', accepted, reason, accepted)
end

local function query_state()
    return PrivateDungeon.get_state()
end

local function register(name, params, callback)
    local definition = y3.eca.def(name)
    for _, param in ipairs(params or {}) do
        definition:with_param(param[1], param[2])
    end
    definition:with_return('结果', 'table'):call(callback)
end

register('轻量副本 - 创建私人副本', nil, create_private_dungeon)
register('轻量副本 - 获取副本口令', nil, get_dungeon_token)
register('轻量副本 - 加入口令副本', { { '副本口令', 'string' } }, join_private_dungeon)
register('轻量副本 - 返回大厅', nil, return_lobby)
register('轻量副本 - 重新查询状态', nil, query_state)
```

轻量 ECA 对外调用接口的 `accepted = true` 只表示本地已发出引擎请求。其 `reason` 也只来自 Lua 的本地前置检查，不能承载平台最终拒绝原因。它不等于平台已经完成切图，也不承诺最终一定进入目标地图。若目标项目需要自定义完成事件，可以在这五个函数之外增加项目自己的 UI 状态通知，但不要因此引入完整 `BOB` 对外调用接口或伪造跨地图完成回调。

## `cross_map_tracking = degraded` 的准确含义

`cross_map_tracking = 'degraded'` **只代表跨地图追踪能力降级**：请求发出后，当前地图中的 Lua/ECA 运行环境无法持续观察新地图的加载结果。

它不表示：

- 已经进入目标地图。
- 目标地图入口已经执行。
- 口令已经可读取。
- 加入玩家已经完成初始化。
- 平台不会再因容量、时间窗或口令状态拒绝请求。

因此创建、口令加入或返回大厅后，都要等待目标地图实际加载，再调用 `轻量副本 - 重新查询状态`。创建者还要在副本地图重新调用 `轻量副本 - 获取副本口令`，不能在旧大厅地图读取并缓存 `space_id`。

## 中途加入与玩家初始化钩子

口令加入会让客户端 B 在副本已经运行后触发目标地图的“玩家-加入游戏”。目标项目必须让首批进入和中途加入走同一个初始化钩子，并保证同一玩家重复触发时不会重复初始化。

下面仅表示接线职责；`initialize_project_player` 必须替换为目标项目已有的玩家数据、镜头或玩法初始化入口，不得复制当前项目的战斗或单位生成逻辑。

```lua pseudocode
local initialized_players = {}

local function initialize_project_player_once(player, is_middle_join)
    local player_key = tostring(player:get_id())
    if initialized_players[player_key] then
        return
    end
    initialized_players[player_key] = true
    initialize_project_player(player, is_middle_join)
end

y3.game:event('玩家-加入游戏', function(_, data)
    initialize_project_player_once(data.player, data.is_middle_join == true)
end)
```

幂等键应选择目标项目中跨回调稳定的玩家标识。若项目已有“玩家-加入游戏”监听器，应在原监听器中调用钩子，不要再注册一套会重复执行的并行初始化流程。`data.is_middle_join` 可用于加载已开始对局所需的状态，但不能作为“是否需要初始化”的唯一判断；首批玩家和中途加入玩家都需要初始化。

## 双客户端验证

本地语法检查不能证明平台跨图和补人行为。完成静态检查后，使用两个真实客户端按顺序验证：

1. 客户端 A 在大厅调用创建函数。Lua 路径确认返回 `true`；薄 ECA 路径确认返回 `accepted = true`，且 `cross_map_tracking` 为 `degraded`。两者都只证明本地调用已发出。
2. 等客户端 A 实际进入副本地图，再重新查询状态并获取非空 `dungeon_token`。
3. 在 `can_add_in_time` 时间窗内，客户端 B 留在大厅并使用该口令加入；确认 B 实际进入同一副本。
4. 检查 A 与 B 的目标项目玩家初始化钩子各执行一次；B 的回调可观察到中途加入状态，重复事件不会重复初始化。
5. 由 A 或 B 调用返回大厅；等待大厅地图实际加载，再重新查询状态，确认当前为大厅上下文且副本口令为空。

另外记录三类平台拒绝结果：无效口令、房间已满、超过 `can_add_in_time`。以平台提示、运行日志和客户端实际停留上下文为证据；这些拒绝是配置和平台状态边界，不能用本地 `accepted` 或本地 `reason` 替代验证。

静态检查至少包括：

```powershell
lua -e "local f,e=loadfile('maps/EntryMap/script/private_dungeon.lua'); if not f then error(e) end"
rg -n "request_create_private_dungeon|request_join_private_dungeon|get_dungeon_info" maps
```

将命令中的路径替换为目标项目实际模块位置。若大厅和副本各有脚本副本，还要比较两份模块，确认没有漂移。

## 回滚路径

轻量接入应保持可独立撤销：

1. 停止 UI/ECA 调用五个轻量函数，恢复目标项目原有入口。
2. 从大厅和副本地图入口删除本次新增的 `include 'private_dungeon'` 及轻量 ECA 对外调用接口的 `include`，不覆盖其他入口代码。
3. 移除本次新增的五个轻量 ECA 函数定义；不要删除目标项目原有自定义事件或函数。
4. 恢复接入前的大厅、副本和 `dungeon.json` 配置备份，重点核对模式、`enable_private`、`max_player_num` 与 `can_add_in_time`。
5. 移除新增的玩家初始化委托，恢复原钩子；确认没有遗留的重复监听器。
6. 重新运行 Lua 语法检查，并分别启动大厅与副本地图，确认入口无缺失模块错误。

回滚只针对本章新增的轻量模块和接线。不要通过恢复整个 `script/`、地图目录或项目配置目录来回滚，这会覆盖目标项目的其他改动。
