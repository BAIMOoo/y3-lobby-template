# 迁移

[返回文档首页](./README.md)

本章说明如何把大厅服务框架接入目标项目。迁移重点是复制框架文件、配置项目 JSON、创建 ECA 完成事件。不要照抄测试项目的关卡、模式、匹配规则或玩法逻辑。

迁移包位于 `docs/游戏大厅系统/迁移包/`。包内只应包含：

- `script/y3/**`
- `需要合并到项目/custom/protocol/protocol.pb`

迁移包不包含外部项目配置器、测试 UI、测试项目玩法脚本、地图文件、ECA 函数编号或项目专属配置。

## 三层配置边界

配置按下面三类处理：

| 类型 | 由谁维护 | 放在哪里 | 示例 |
| --- | --- | --- | --- |
| 框架内部固定值 | 框架维护 | `script/y3/game/lobby/**` | 玩家协议 `version` 固定为 `"2.0"`；`service.pb`；BOB 服务端点 |
| 项目配置 | 项目作者维护 | `gamemode.json`、`match.json`、`dungeon.json`、`custom/protocol/protocol.pb` | 模式、目标关卡、最大人数、最少人数、中途加入时间 |
| 每次调用参数 | Lua 或 ECA 调用者传入 | `y3.lobby` 或 `Bind` 表 | 建立连接使用的玩法 ID、队伍人数上限、匹配目标、分数、队伍编号、AID、聊天内容、口令 |

简单理解：

- 固定规则放在框架里，作者不用传。例如跨房合流玩家数据里的 `version` 固定由框架写入 `"2.0"`。
- 项目规则放在 JSON 里。例如模式、关卡、人数上限、最少人数和中途加入时间。
- 每次操作必须由调用方明确提供的数据由对外调用接口传入。例如建立连接的玩法 ID、本次创建队伍的人数上限、本次匹配的 `level_id` 和 `game_mode`。

不要把测试项目里的模式编号或关卡编号当成固定值。目标项目应使用自己的 `gamemode.json`、`match.json` 和 `dungeon.json`。

## 迁移步骤

1. 备份目标项目的 `script/y3/`、`custom/protocol/protocol.pb`、`gamemode.json`、`match.json`、`dungeon.json`、ECA 函数和自定义事件。
2. 将迁移包中的 `script/y3/` 复制到需要使用大厅服务的关卡脚本目录。
3. 将迁移包中的 `需要合并到项目/custom/protocol/protocol.pb` 合并到目标项目的 `custom/protocol/protocol.pb`。
4. 按目标项目实际关卡配置 `gamemode.json`、`match.json`、`dungeon.json`。
5. Lua 项目在地图脚本中调用 `y3.lobby.connect(玩法ID)`；ECA 项目创建 `大厅服务请求完成` 事件，并通过编辑器“执行 Lua 代码”调用 `Bind` 表中的大厅服务接口。
6. 按 [验证与故障排查](./05-验证与故障排查.md) 完成本地检查和平台运行检查。

目标项目已经有 `script/y3/` 时，先备份再合并。纯 ECA 项目如果没有初始化过 `y3-lualib`，可以直接复制迁移包中的 `script/y3/`。

## 启动脚本

Lua 入口只需要加载 `y3`，然后在玩家进入大厅后建立连接：

```lua
local y3 = require 'y3'

y3.game:event('玩家-加入游戏', function (_, player)
    local result = y3.lobby.connect(10190356)
    if not result.accepted then
        print('大厅服务连接请求未发出：' .. tostring(result.reason))
    end
end)
```

`y3.lobby.connect(玩法ID)` 需要传入正整数玩法 ID。上例 `10190356` 是当前示例项目的玩法 ID；迁移到自己的项目时，必须改成目标项目对应的玩法 ID。这个值不是调试参数，也不是 UUID 格式的 `map_id`，框架不会自动从运行环境读取。

玩法 ID 的填写方式：项目上传并审核通过后，在平台审核后台查看对应的数字玩法 ID；无法查看时向平台运营确认。Lua 作者把该数字传给 `y3.lobby.connect(...)`，ECA 作者把它填入“大厅服务 - 建立连接”的“玩法ID”整数参数。它不写在 `gamemode.json`、`match.json` 或 `dungeon.json` 中。

`connect(玩法ID, 是否在游戏关卡)` 是建立连接和重新建立连接的唯一入口。第二个参数可选，默认为 `false`；在目标玩法关卡内建立连接时传 `true`。组队、匹配、聊天、跨房合流和高级查询接口需要先连接；同房分流、加入口令、获取口令、返回大厅和退出游戏不要求预先连接。

## 配置 `gamemode.json`

`gamemode.json` 声明项目有哪些模式。下面只是格式示例，模式编号和名称要换成目标项目自己的值。

```json
{
  "game_modes": {
    "LOBBY_MODE_ID": { "desc": "大厅" },
    "MATCH_MODE_ID": { "desc": "匹配玩法" },
    "TARGET_MODE_ID": { "desc": "指定关卡玩法" }
  },
  "lobby": 0
}
```

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `game_modes` | 对象 | 键是字符串形式的模式 ID，值是该模式配置 |
| `desc` | 字符串 | 模式显示名称 |
| `lobby` | 整数 | 平台用于表示大厅的字段；目标项目已有值时保留原值 |

## 配置 `match.json`

`match.json` 配置匹配规则。目标项目已有匹配规则时，追加或调整需要接入大厅服务的规则，不能直接覆盖整个文件。

```json
[
  {
    "game_mode": "MATCH_MODE_ID",
    "level_id": "MATCH_LEVEL_ID",
    "teams": [2],
    "diffuse_time": [10],
    "sections": [
      { "min_player_num": 2, "max_score": 6900 }
    ]
  }
]
```

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| 根节点 | 数组 | 每一项是一条匹配规则 |
| `game_mode` | 整数或字符串 | 匹配使用的模式，必须存在于 `gamemode.json.game_modes` |
| `level_id` | 字符串 | 匹配成功后进入的关卡 ID |
| `teams` | 整数数组 | 队伍人数配置，例如 `[1]`、`[2]`、`[4]` |
| `diffuse_time` | 整数数组 | 匹配扩散时间配置，具体含义以平台规则为准 |
| `sections` | 数组，可选 | 分数分段配置 |
| `min_player_num` | 整数 | 该分段允许开始匹配的最少人数 |
| `max_score` | 整数 | 该分段的最高分数 |

最大人数、最少人数、分段分数这类规则优先放在 JSON 里配置。调用“开始匹配”时传本次要匹配的 `level_id`、`game_mode`，`score` 可选。

## 配置 `dungeon.json`

`dungeon.json` 配置每个关卡支持哪些模式，以及这些模式是否允许公开进入、指定进入和中途加入。

```json
{
  "MATCH_LEVEL_ID": {
    "game_modes": {
      "MATCH_MODE_ID": {
        "enable_public": 0,
        "enable_private": 1,
        "max_player_num": 8,
        "can_add_in_time": 120
      }
    }
  }
}
```

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| 顶层键 | 字符串 | 关卡 ID，通常要与 `match.json.level_id` 对应 |
| `game_modes` | 对象 | 该关卡支持的模式列表 |
| `enable_public` | `0` 或 `1` | 是否允许平台公开进入 |
| `enable_private` | `0` 或 `1` | 同房分流、跨房合流、加入口令进入的模式需要启用 |
| `max_player_num` | 整数 | 该关卡和模式允许的最大人数 |
| `can_add_in_time` | 整数 | 允许中途加入的时间值，单位以平台规则为准 |

配置后检查：

1. `match.json[*].game_mode` 存在于 `gamemode.json.game_modes`。
2. `match.json[*].level_id` 存在于 `dungeon.json` 顶层。
3. `dungeon.json.<关卡ID>.game_modes.<模式ID>` 存在，并按同房分流、跨房合流、加入口令的需要启用。

`setting.json` 没有大厅服务框架要求直接覆盖的字段。

同房分流参数表可以额外提供 `players`；每项格式为 `{ aid = 玩家AID }`。提供时仅列表内玩家切换，省略时当前房间内调用到该接口的玩家都会执行。

## 协议与连接阶段

`script/y3/game/lobby/proto/service.pb` 随框架复制，不需要项目作者维护。

`custom/protocol/protocol.pb` 属于项目资源。目标项目没有同名文件时可以复制；已有同名文件时不能直接覆盖，应由协议维护方合并后重新生成。

加载 `script/y3` 时，框架只注册 Lua 与 ECA 对外调用接口，不创建 BOB 客户端、不读取协议文件、不创建网络对象。只有调用 `connect(玩法ID, 是否在游戏关卡)` 时，框架才加载 `service.pb`、项目 `protocol.pb`，并按当前平台环境选择内部服务端点。

连接时使用的玩法 ID 是必填调用参数。Lua 调用 `y3.lobby.connect(玩法ID, 是否在游戏关卡)`；ECA 调用“大厅服务 - 建立连接”时传入“玩法ID”，并可选传入“是否在游戏关卡”。玩法 ID 缺失、不是整数或小于等于 0 时，接口会立即返回 `invalid_game_play_id`。

玩法 ID 应填写目标项目自己的值。当前示例项目使用 `10190356`，只能作为示例；迁移到其他项目时不要照抄。

## ECA 完成事件

ECA 项目需要在主关卡创建自定义事件：

- 事件名：`大厅服务请求完成`
- 参数名：`回调数据`
- 参数类型：字典

只创建事件和参数，不复制其他项目的事件编号。未创建事件时，需要完成事件的 ECA 对外调用接口会返回 `accepted = false`、`code = event_missing`。

还可以按需创建状态变化事件：

- 事件名：`大厅服务状态变化`
- 参数名：`事件数据`
- 参数类型：字典

这个事件用于接收连接、队伍、匹配、聊天等状态变化。未创建时不会阻断业务，也不会让接口返回 `event_missing`；只是收不到状态变化通知。`大厅服务请求完成` 仍然是异步接口的必需事件。

## ECA 调用方式

初始化 `script/y3` 后，框架会注册 27 个 `Bind` 对外调用接口。ECA 作者不需要把 `tools/eca/*.json` 合并进目标项目，也不需要复制其他项目的函数编号或触发器编号。

在编辑器里添加“执行 Lua 代码”，填写：

```lua
local call = Bind['大厅服务 - 建立连接']
return call(args[1])
```

如果当前关卡是目标玩法关卡，可把第二个参数传为 `true`：

```lua
local call = Bind['大厅服务 - 建立连接']
return call(args[1], true)
```

有参数时：

```lua
local call = Bind['大厅服务 - 创建队伍']
return call(4)
```

参数表接口：

```lua
local call = Bind['大厅服务 - 开始匹配']
return call({
    level_id = 'MATCH_LEVEL_ID',
    game_mode = 'MATCH_MODE_ID',
    score = 1000,
})
```

迁移完成后，按项目使用方式阅读 [Lua 功能使用](./03-Lua功能使用.md) 或 [ECA 功能使用](./04-ECA功能使用.md)。
