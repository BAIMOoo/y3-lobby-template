# 验证与故障排查

[返回文档首页](./README.md)

本章用于确认迁移是否可用。本地检查只能证明文件、文档和接口定义一致，不能证明真实平台上的登录、匹配、聊天、局内私人副本、加入口令、获取口令、返回大厅或退出游戏已经成功。

## 本地检查

在项目根目录执行：

```powershell
py -3 tests/documentation_examples_test.py
py -3 tests/eca_lobby_eca_json_test.py
lua tests/eca_lobby_api_contract_test.lua
lua tests/lobby_embedded_protocol_test.lua
py -3 -m py_compile tests/documentation_examples_test.py
```

五个命令退出码都应为 0。缺少 `lua`、`py` 或测试依赖时，记录缺少的条件，补齐后重新执行。

同时检查：

- 文档导航顺序为项目概览、迁移、Lua 功能使用、ECA 功能使用、验证与故障排查。
- 迁移包只包含 `script/y3/**` 和 `需要合并到项目/custom/protocol/protocol.pb`。
- 文档和 ECA 名称使用“局内私人副本”“加入口令”“获取口令”。
- 文档、Lua 接口表和 ECA 接口表都按 26 个 ECA 对外调用接口说明。
- 旧“同房分流”和“跨房合流”只允许出现在底层解释或明确废弃说明中，不得作为正式 Lua/ECA 接口或操作步骤出现。
- `gamemode.json`、`match.json`、`dungeon.json` 中模式、关卡、人数配置互相对应。
- `custom/protocol/protocol.pb` 已合并到目标项目。
- 主关卡已创建 `大厅服务请求完成`，并添加字典参数 `回调数据`，未复制其他项目事件编号。
- 如需实时状态通知，主关卡可创建 `大厅服务状态变化`，并添加字典参数 `事件数据`；未创建时不阻断业务。
- `setting.json` 未被测试项目配置覆盖。

## 平台运行检查

按顺序验证。前一项失败时先修复，再继续下一项。

| 检查项 | 操作 | 通过标准 |
| --- | --- | --- |
| 地图启动 | 分别启动大厅地图和目标关卡地图 | 无 Lua 加载错误、协议错误、重复初始化错误 |
| 建立连接 | 在大厅地图中用 Lua 调用 `y3.lobby.connect(玩法ID)`，或用 ECA 调用“大厅服务 - 建立连接”并传入玩法 ID；在目标玩法关卡建连时额外传入“是否在游戏关卡”为 `true` | 得到明确成功、失败原因或结果码 |
| 查询状态 | Lua 调用 `y3.lobby.get_state()`，或 ECA 调用“大厅服务 - 获取状态快照” | 能看到 `status` 和 `failed_events` |
| 状态变化事件 | Lua 订阅 `y3.lobby.on_event(...)`，或 ECA 创建 `大厅服务状态变化` 后监听 `事件数据` | 能收到稳定事件名，例如 `connection_changed`、`team_changed`、`message_received`；Lua 调用 `listener:remove()` 后不再收到 |
| 队伍 | A 创建队伍，B 加入队伍，验证队长权限 | 两个客户端队伍成员一致 |
| 聊天 | 发送世界聊天和队伍聊天 | 对应玩家能收到消息 |
| 匹配 | 传入 `level_id`、`game_mode`，可选传入 `score` | 模式和目标关卡符合项目 JSON |
| 局内私人副本：无队伍 | 传入 `level_id`、`game_mode`、`max_player`，不预先连接 BOB 也要测试一次 | 立即结果包含 `route = solo_engine`、`completion_mode = request_only`、空 `request_id`；`accepted = true` 只证明请求已提交 |
| 局内私人副本：有队伍 | 队长传入目标关卡、模式和容量；队伍成员包含明确非游戏中、游戏中和未知状态三类 | 只带明确 `in_game == false` 的成员；跳过游戏中成员，排除未知状态成员；组队结果包含非空 `request_id` 并走完成事件 |
| 局内私人副本：失败不降级 | 制造未连接、未就绪、目标参数拒绝或服务拒绝 | 返回明确失败；`platform_requested = false`、`entered_target = not_entered`；引擎单人请求数为零，所有人保持原地 |
| 获取口令 | 进入目标关卡后获取口令，不预先连接 BOB 也要测试一次 | 返回非空口令 |
| 加入口令 | 另一名玩家使用口令进入，不预先连接 BOB 也要测试一次 | 在人数和中途加入时间允许时进入同一目标关卡 |
| 列表单项读取 | Lua 调用 `get_member(1)`、`get_chat_message(1)`，或 ECA 调用对应接口 | 能按序号读取单个队伍成员和单条聊天消息 |
| 高级查询 | 已连接后调用获取队伍信息、获取玩家信息、刷新玩家信息 | 队伍查询异步完成；玩家信息缓存命中时同步返回、未命中时异步完成；刷新玩家信息把本机状态上传到大厅服务 |
| 返回大厅 | 分别在未连接、队伍中、匹配中传入大厅 `level_id`、`game_mode`、`max_player` | 立即提交换图；不触发取消匹配、离队、删除玩家信息或 BOB 销毁；回到大厅后重新建立连接并查询原队伍状态 |
| 退出游戏 | 分别在未连接、空闲、队伍中、匹配中调用退出 | 未连接时直接退出；已连接时清理后退出 |
| 返回或退出期间重复操作 | 在建立连接或其他功能请求尚未完成时调用返回大厅或退出游戏 | 旧请求只收到一次 `cancelled_by_terminal`；返回大厅提交后恢复原连接状态并允许重试；退出清理期间继续使用终态锁拒绝冲突操作 |

真实 BOB 双客户端条件不可用时，最终记录应写明：

`Not-tested: 真实 BOB 双客户端 e2e，原因：<具体原因>`

不能用本地 fake 测试替代真实双客户端结论。

局内私人副本的单人 `request_only` 路由、加入口令和返回大厅的 `accepted = true` 只证明本地流程已提交，不是平台成功证据。局内私人副本单人路由应包含 `route = 'solo_engine'`、`completion_mode = 'request_only'`；加入口令和返回大厅应包含 `cross_map_tracking = 'degraded'`，且不会触发 `大厅服务请求完成`。只有新地图实际加载并重新查询到目标模式、关卡和口令，才能记录为通过。

## 故障排查

| 现象 | 优先检查 | 修复后复测 |
| --- | --- | --- |
| 启动时报 `y3` 不存在 | 是否复制 `script/y3/`，入口是否正确加载 `y3` | 重启地图 |
| 日志提示 `service.pb: No such file or directory` | `script/y3/game/lobby/proto/service_pb.lua` 是否存在；是否还在使用旧版 `proto_helper.lua` | 重新复制最新 `script/y3/` 后上传 |
| 建立连接失败 | 玩家 AID、玩法 ID、协议文件、平台服务、网络、是否重复连接 | 再次调用建立连接 |
| 返回 `invalid_game_play_id` | 建立连接时是否传入正整数玩法 ID，是否误填 UUID 格式的 `map_id` | 改为目标项目对应的玩法 ID 后重试 |
| 对外调用接口返回 `not_connected` | 是否已建立连接 | 连接成功后重试 |
| 对外调用接口返回 `connection_pending` | 连接是否仍在进行 | 等待连接结果后重试 |
| 返回 `no_eligible_players` | 有队伍但没有明确 `in_game == false` 的可带入成员 | 等队伍成员状态刷新，或由合格队长重新发起 |
| 返回 `rpc_failed` 且有 `result_data.remote_error_code` | 远端返回了框架未识别的原始错误码 | 记录原始错误码并结合平台日志定位 |
| 请求完成结果返回 `cancelled_by_terminal` | 是否在旧请求未完成时调用了返回大厅或退出游戏 | 按取消处理旧请求，不要继续等待旧请求 |
| 建立连接返回 `connection_closing` | 是否正在返回大厅或退出游戏 | 返回大厅后重新建立连接；退出游戏后重新登录 |
| 其他功能返回 `terminal_in_progress` | 是否正在返回大厅或退出游戏 | 等返回或退出完成后再操作 |
| 返回或退出返回 `terminal_locked` | 是否重复点击返回大厅或退出游戏 | 等第一个返回或退出请求完成 |
| 普通异步 ECA 返回 `event_missing` | 主关卡是否创建 `大厅服务请求完成` 和 `回调数据` | 重新触发同一接口；三项请求提交型跨图接口不需要该事件 |
| 收不到状态变化事件 | 是否创建可选事件 `大厅服务状态变化` 和字典参数 `事件数据` | 触发连接、组队或聊天操作 |
| 普通异步请求已发出但收不到完成事件 | 事件名、参数名、监听触发器、`failed_events` | 获取状态快照；三项请求提交型跨图接口应等待切图而不是完成事件 |
| 创建队伍失败 | 是否传入有效人数上限，当前是否已在队伍中 | 再次创建队伍 |
| 匹配进入错误关卡 | `match.json.level_id`、`gamemode.json.game_modes`、`dungeon.json` 顶层键 | 再次匹配 |
| 局内私人副本单人请求未切图 | 检查实际运行包、目标模式、关卡 UUID、私有实例开关和平台配置 | 不能用本地 `accepted` 判定成功；以新地图加载和状态重查为准 |
| 局内私人副本组队失败 | `game_map_id`、队长权限、成员 `in_game` 三态、目标模式、完成事件是否存在 | 由队长再次发起局内私人副本；不得降级为单人 |
| 加入口令失败 | 口令是否过期、人数是否已满、`can_add_in_time` 是否结束 | 获取新口令后重试 |
| 返回大厅后队伍状态丢失 | 是否误走了退出清理、是否在新地图重新建立连接并查询远端状态 | 确认返回大厅未调用 `cleanup_before_exit`，再在大厅重新连接查询 |
| 退出后仍看到旧队伍或旧匹配 | 是否通过 `y3.lobby.exit_game()` 或“大厅服务 - 退出游戏”退出 | 重新登录后检查 |

## 验收记录

每次验证至少记录：

- 调用方式：Lua 或 ECA。
- 项目版本和配置版本。
- 平台环境。
- 客户端数量和玩家 AID。
- 调用的对外调用接口、参数；普通异步请求记录 `request_id`，局内私人副本记录 `route`、`completion_mode`、`selected_players`、`skipped_in_game_players`、`unknown_status_players`、`platform_requested` 和 `entered_target`，加入口令和返回大厅记录 `cross_map_tracking`。
- 切换前后的地图和模式。
- 结果：通过、失败、未验证或不适用。
- 日志位置。

最终交付时，本地检查应通过；真实 BOB 双客户端无法执行时，应按上面的 `Not-tested` 格式写明原因。
